# CRM Spec Kit Scope

Artifacts in this directory use the CRM kit workflows. Read the installed kit INSTALL.md and project config `.agents/crm-spec-kit.json` from the repository root. Do not change source documents or shared repository instructions. Higher-priority workspace instructions still apply; surface conflicting requirements to the owner. Check/review workflows write records only. No automatic commit, push, ticket mutation or approval.

Use artifact_paths from the context bundle; missing layout in older configs means legacy. Do not rename project folders during install/update. Read the kit's knowledge-records-and-evidence reference when processing meetings/chat, decisions, assumptions or constraints. New DEC/ASM/CST use metadata schema 3 without state fields. Read meeting notes from configured workstream.sources, including new Markdown files in directory sources. Never scaffold a meeting folder in spec, including legacy workstreams. Meeting notes remain input sources outside spec; do not create Meeting records or MTG IDs. Extract ASM/DEC/CST with evidence, or leave an explicit question when the source is insufficient. Legacy artifacts remain readable. Pin evidence and affected scope/revisions; a recorded discussion or action item is not authority approval or a product Task. lint --gate checks declared record obligations. For workstreams with prototype_gate enabled, the revision áp dụng gate also verifies Prototype evidence pins. Human review and approval are evaluated separately.

Apply the installed kit references/artifact-writing-standard.md to every newly authored or edited artifact. Read business content before metadata; preserve schema, source IDs, evidence and approval semantics. Package update does not authorize rewriting historical artifacts or shared instructions.

CRM 3.0.0 uses one current artifact per target/scope and Git for history; no per-run reports or archives. For authorized commits read the kit references/commit-message-policy.md and run scripts/commit_policy.py validate before committing. Never bypass hooks. Existing project instructions and policies remain authoritative.
